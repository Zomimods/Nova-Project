# SAMI Live TV — V20 parity APK

هذا المشروع هو نفس مشروع Android القائم، بعد إصلاح طبقة الواجهة بحيث تستخدم نسخة V20 الكاملة المضمّنة داخل الـ APK بدل واجهة Compose مختلفة عن الموقع.

## ما تم تغييره

- الإبقاء على المشروع Android الحالي وبنيته وخدمات التشغيل والبيانات الموجودة، بدون إعادة إنشاء المشروع من الصفر.
- إضافة `app/src/main/assets/v20/index.html`، وهي نسخة مستقلة من V20 تجمع HTML/CSS/JS وقاعدة القنوات ومنطق المشغّل والمزايا الموجودة في V20.
- جعل `MainActivity` يعرض V20 المضمّن داخل WebView محليًا، لذلك واجهة الـ APK لا تعتمد على تحميل واجهة الموقع نفسها من الويب.
- تفعيل JavaScript وDOM Storage والكوكيز ووسائط التشغيل، والسماح بمصادر HLS التي تحتاج HTTP بما يتوافق مع بيانات V20.
- إضافة صلاحية الميكروفون لتعمل ميزة الصوت/البحث الصوتي عندما يطلبها V20.

## المزايا الموروثة من V20

واجهة الصفحة الرئيسية، الأقسام والبحث، المفضلة وسجل المشاهدة، الحساب والمزامنة مع Firebase، الوضع الداكن/الفاتح، العربية/الإنجليزية، صفحة المشاهدة المنفصلة، مشغل HLS ومصادر الجودة، المشاركة، Picture-in-Picture، لقطة الشاشة، التسجيل عند دعم WebView، التعليقات، الذكاء الاصطناعي، الأوضاع الذكية وPWA/offline surfaces، والتنقل الخاص بالموبايل.

## البناء

المشروع يستخدم Gradle Wrapper ويستهدف Android SDK 34 وminSdk 26.

قبل البناء، تحقق من أن واجهة V20 المضمّنة مطابقة لملف المصدر:

```bash
python3 extract_v20.py --check
```

لإعادة إنشاء الملف المضمّن بعد تعديل `V20.xml`:

```bash
python3 extract_v20.py
```

في بيئة لا تحتوي على Gradle/Android SDK مؤقتًا، لا يمكن اعتبار APK النهائي مبنيًا أو مختبرًا على جهاز حقيقي حتى يمر `assembleDebug` أو `assembleRelease` بنجاح.

## Firebase

واجهة V20 تستخدم إعداد Firebase Web المضمّن في `V20.xml` للمصادقة وRealtime Database. تحقّق من أن المشروع المقصود مضبوط في الملف، وراجع قواعد Realtime Database قبل النشر. ملف `google-services.json` اختياري للطبقة Android الأصلية ولا يغيّر إعداد Firebase الخاص بواجهة V20. التفاصيل في `firebase/FIREBASE_SETUP.md`.

تفاصيل الإصلاح وما لم يُختبر موجودة في `FIX_SUMMARY_AR.md` و`RELEASE_READINESS.md`.
